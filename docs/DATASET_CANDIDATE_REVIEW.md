## Upstream OASIS terms checked

The [official OASIS access page and Data Use Agreement](https://sites.wustl.edu/oasisbrains/home/access/) state that:

- OASIS data are for non-commercial academic research purposes; commercial use requires explicit prior written authorization.
- Users may not share, distribute, or otherwise make OASIS data available to third parties, including collaborators, without prior written permission from OASIS. Collaborators must independently apply and agree to the terms.
- Data must be held on secure, access-controlled systems accessible only to the authorized user.
- Appropriate OASIS acknowledgment and citations are required for presentations/publications benefiting from OASIS data.
- The official OASIS site says access is hosted through NITRC-IR and applications are reviewed by OASIS staff.
- The official OASIS overview describes OASIS-1 as 416 cross-sectional subjects and a separate 20-subject reliability set. The derivative card's "436 subjects" claim may count these together, but its exact participant/session mapping was not verified.

These terms make a mirror's public availability or an uploader-selected CC0/other label insufficient proof of authority to redistribute the underlying data. This review is not legal advice or an approval determination. Obtain the official access decision for the intended project from OASIS/the responsible institution before data acquisition.

## Overlap and duplicate assessment

- **Kaggle and GitHub:** Likely contain the same two OASIS tables. Evidence: GitHub's README points readers to Kaggle as an acquisition route; both list the same exact CSV file names and byte sizes; the cross-sectional CSV schema and opening rows returned by the GitHub raw endpoint match the known OASIS-1 table layout. We did not download both files or calculate matching content hashes, so exact identity is not claimed.
- **Hugging Face pzarzycki:** Explicitly claims OASIS-1 and includes an OASIS clinical CSV plus OASIS-identified volumes. Its OASIS participants overlap the OASIS source population by construction, but actual participant IDs/coverage and deduplication have not been audited.
- **Hugging Face VashuTheGreat2:** The repository has no source card/license and exposes class-named files/metadata and image archives. It is not possible to establish whether its images or subjects overlap OASIS, Kaggle, or the GitHub mirror from repository metadata alone.
- **Do not combine any of these sources.** Exact cross-file participant overlap, row duplicates, and session rules require authorized copies and official dictionaries. Matching source names or file naming is not enough to establish join keys.

## Feature/label suitability for MindScan

The cross-sectional and longitudinal OASIS tables contain demographics, clinical scales (including CDR/MMSE), MRI-derived values (eTIV, nWBV, ASF), and visits. The current application feature allowlist is limited to saved memory, attention, orientation, language-task measures, and descriptive speech measures (see [data dictionary](./data-dictionary.md)). The reviewed OASIS candidates do not provide those application task responses or validated equivalent measurements.

Using CDR as a target while including MMSE, age, demographic fields, or MRI-derived values would answer a different question, can encode clinical/target information, and cannot produce a model compatible with the live MindScan assessment. The candidate multi-class image dataset is likewise not an input match. Therefore even a future authorized OASIS tabular baseline must remain a separate research experiment and must not be wired to MindScan inference without compatible population, features, and labels.

## Acquisition and next steps

1. Do not download any mirror or derivative until OASIS confirms the intended acquisition/use route and any permission for third-party-hosted copies. Prefer the official OASIS/NITRC-IR process.
2. Request written clarification on permitted academic use, whether redistribution through the candidate platforms was authorized, and what derivative/tabular files may be stored or used.
3. If authorized access is granted, acquire only the smallest official clinical CSV needed from the approved source, not image archives. Record its approved release, access reference, retrieval date, byte size, and SHA-256 in a private provenance record.
4. Audit schema and aggregates only after approval: rows, unique participants, sessions, duplicate keys, missingness, CDR label distribution, and the official source's inclusion rules. Do not expose IDs.
5. Exclude MMSE/CDR and all target-defining or disallowed features from predictors. Participant-level splitting is required; training/evaluation still will not be compatible with live MindScan unless its approved task features are present.

### Work performed for this review

Read-only public metadata and documentation were queried: Kaggle dataset API/file list, GitHub repository metadata/tree/README and a partial CSV response, Hugging Face repository API/file lists and the pzarzycki card, the additional Kaggle URL (which returned 403/404), and the official OASIS site/access terms.
